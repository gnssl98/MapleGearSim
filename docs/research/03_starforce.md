## 2. 확률표

### 2.1 일반 장비 (현재 실제 적용 확률, 스타캐치 ×1.05 포함)

- **공식 기본 확률**은 2025-03-20 공지 표를 쓴다(✅). 15성 이상만 공지에 나와 있고, 0~14성 기본값은 기존 값(🟡)이다.
- **실제 적용 확률**은 2026-03-19부터 스타캐치 보정이 항상 들어간 값이다: `성공 = 기본성공 × 1.05`.
  - 나머지 `1 − 성공`은 기존 유지:파괴 비율대로 나뉜다. 즉 `파괴 = 기본파괴 × (1 − 성공) / (1 − 기본성공)`.
  - 나무위키 표가 정확히 이 방식으로 계산돼 있고, 2020년 넥슨 공지의 15성 예시(31.5 / 66.45 / 2.06)와도 맞는다.
- **실패 = 유지**다(하락 없음). 0~14성은 파괴도 없다.

## 3. 비용 공식

### 3.1 1회 강화 비용 (일반 장비)

```
cost(L, S) = round_100( 1000 + L³ × (S+1)^e / d )
  L = 장비 착용 레벨, S = 현재 성급(0→1 시도면 S=0)
  round_100 = 십의 자리에서 반올림(100메소 단위)
```

| 현재 성급 S | e | d | 비고 |
|---|---|---|---|
| 0~9 | 1 | 36 | |
| 10 | 2.7 | 571 | |
| 11 | 2.7 | 314 | |
| 12 | 2.7 | 214 | |
| 13 | 2.7 | 157 | |
| 14 | 2.7 | 107 | |
| 15, 16 | 2.7 | 200 | |
| **17** | 2.7 | **150** | 2025-03-20 인상 |
| **18** | 2.7 | **70** | 2025-03-20 인상 |
| **19** | 2.7 | **45** | 2025-03-20 인상 |

출처: [나무위키](https://namu.wiki/w/%EB%A9%94%EC%9D%B4%ED%94%8C%EC%8A%A4%ED%86%A0%EB%A6%AC/%EC%8A%A4%ED%83%80%ED%8F%AC%EC%8A%A4%20%EA%B0%95%ED%99%94) 🟡. 공식 공지는 17/18/19/21성 비용이 오른다고만 했고 수치는 없다 ✅.

**과거 공식(참고, 사용 금지)**: 0~9 `/25`, 10~14 `/400`, 15~24 `/200`. 이때는 L을 10 단위로 내림했다([velog 2022](https://velog.io/@darkpppet/%EB%A9%94%EC%9D%B4%ED%94%8C-%EC%8A%A4%ED%83%80%ED%8F%AC%EC%8A%A4-%EB%B9%84%EC%9A%A9)).

**검증 예시**:
- 140제 12→13: 공식값 13,051,200. [starforcechallenge](https://starforcechallenge.com/calculator)의 "1,305만"과 일치.
- 200제 12→18 기대비용(아래 5절 모델): 본 조사의 계산이 인벤 글의 샤타 기준 "16.54억, 노작 0.43개"와 일치(본 계산 16.54억, 파괴 0.42회). 15~17성 확률과 제수가 맞다는 근거가 된다.

### 3.2 할인 적용 순서 🟡

```
실지불 = cost × (1 − (MVP% + PC방%)) × (이벤트 ? 0.7 : 1) + (파괴방지 ? cost × 2 : 0)
```

- **MVP**(✅ 2025-04-17 공지): 실버 3%, 골드 5%, 다이아 10%. 레드 등 다이아 이상은 10%로 보는 계산기가 많다 🟡. 브론즈는 0%.
- **PC방**(프리미엄): 5% 🟡.
- MVP와 PC방은 **합적용**이고, 이벤트 30%는 **곱적용**이다.
- 적용 구간 ❓:
  - 공식 공지: MVP 할인은 "17성까지만".
  - 계산기 문구는 제각각이다: "0~16성 강화에만"(starforcechallenge), "17성 미만 구간"(chuchu.gg), "1~17성"(나무위키).
  - **현재 성급 S ≤ 16(결과 17성 이하)으로 구현하고, 설정값으로 노출하는 것을 권장한다.**
- **파괴방지 추가비** `cost × 200%`는 모든 할인에서 제외된다. 30% 할인 이벤트 중 파방 시도 총액은 기본비용의 2.7배가 된다(0.7 + 2).
- 반올림 ❓: 할인 후 금액의 반올림 방식은 확인하지 못했다. 과거 자료에는 "소수점 첫째 자리에서 올림"으로 나온다. 영향이 미미해 무시해도 된다.

### 3.3 파괴방지 ✅

| 항목 | 내용 |
|---|---|
| 적용 구간 | 현재 성급 15, 16, 17(15→16, 16→17, 17→18 시도) |
| 비용 | 1회 비용의 +200%(총 3배). 추가분에는 할인 미적용 |
| 효과 | 파괴 확률 0%("PROTECTED", 결과는 유지와 같음) |
| 자동 강화 | 성급별로 파방 on/off 설정 가능 |

- 18성 이상에서는 파괴방지가 불가능하다.
- 15성 100% 이벤트 중에는 파방이 무의미하다. 확정 성공이므로 파방을 끄고 진행하는 것이 유리하다.

## 5. 파괴/복구

### 5.1 파괴 시 흔적(Trace) ✅ (2026-03-19 이후)

- 15성 이상에서 파괴되면 **장비의 흔적**이 생긴다. 흔적은 잠재·에디·주문서 강화·추옵·소울·교환 조건을 보존하고, 거래할 수 없다.
- 흔적의 성급은 파괴 직전 성급이다. **23성 이상에서 파괴되면 22성**으로 저장된다.

## 7. 기댓값 계산 방법 (마르코프 체인 모델)

### 7.1 상태와 전이
- 상태 `s ∈ {start, …, target}`이고, `target`은 흡수 상태다.
- 상태 `s`에서 1회 시도하면 다음과 같이 전이한다.
  - 성공 `p_s` → `s+1`(1+1 이벤트면 `s+2`, 1516 이벤트면 `p_s=1`).
  - 유지 `f_s` → `s`(자기 루프). **하락이 없어** 체인이 단방향에 가깝다.
  - 파괴 `d_s` → 복구 정책에 따른 상태 `r(s)`. 동시에 스페어 비용과 복구 메소가 든다.
    - 기본 복구: `r(s)=12`, 스페어 1개.
    - 확정 복구: `r(s)=min(s,22)`, 스페어 N(s)개, 메소 R(s,L).
  - 파방 사용 시 `d_s=0`이고 비용은 `3×cost`(할인은 1배분에만 적용)다.
- 1회 비용은 `c_s`(할인·이벤트 반영)다.

### 7.2 기대 비용 방정식
자기 루프를 소거하면 다음과 같다.
```
E[s] = ( c_s + p_s·E[s+1] + d_s·(K_s + E[r(s)]) ) / (p_s + d_s)
K_s  = 파괴 1회당 복구 비용 = N(s)·스페어가격 + R(s,L)   (기본 복구면 1·스페어가격)
E[target] = 0
```
- `r(s) ≤ s`(되돌아감)이므로 연립일차방정식 `(I − Q)E = b`를 풀면 된다. 상태가 31개 이하라 가우스 소거로 즉시 풀린다.
- 기본 복구만 쓰면 모든 E[s]를 `a_s + b_s·E[12]`로 두고 뒤에서부터 계산한 뒤 `E[12]`를 닫힌 형태로 구할 수 있다(본 조사 스크립트 방식).
- 같은 체인으로 다음도 구한다.
  - 기대 파괴 횟수(비용 대신 `d_s`를 누적).
  - 기대 시도 횟수(`c_s=1`).
  - 분산: 2차 모멘트 방정식 `M2[s] = …`을 같은 구조로 풀거나 몬테카를로로 구한다.
- **분포**(상위 10%/90% 비용 등)는 기대값만으로 알 수 없다. **몬테카를로**(10만 회 이상, mesu.live 기본값)나 비용 이산화 DP가 필요하다. 나무위키에 따르면 21→22 구간 비용은 분포 편차가 매우 크다.

### 7.3 정책 최적화 (복구·파방 선택)
- 각 파괴 성급마다 "기본 복구(12성)"와 "확정 복구"를 고르고, 각 15~17성마다 파방 on/off를 고르면 **MDP**가 된다.
- 목적함수 최소화는 정책 반복(Policy Iteration)이나 값 반복으로 푼다. 행동 조합은 2³ × 2⁸ 정도라 전수 탐색도 가능하다.
- 기존 계산기들의 "강화 최적화" 기능이 이것이다.
  - chuchu.gg 예시: 파방 15/16/17, 확정복구 15~22 자동 선택.
  - starforcechallenge 예시: 확정복구 15·20·21성, 나머지는 12성 복구.

## 8. 프로그램 설계 시 시사점

1. **데이터 주도 설계**
   - 확률표(기본 성공/파괴 + 스타캐치 배수), 비용 제수표, 복구 테이블(N(s), R(s,L)), 최대 성급표를 **버전 태그가 붙은 JSON/YAML**로 분리한다. 예: `kms_2026-03-19`.
   - 이렇게 하면 패치 때 코드 수정 없이 교체할 수 있다. 2025-03 이전, 2026-03 이전 규칙도 별도 프로파일로 두면 구형 계산기와 비교하기 쉽다.
2. **확률은 "기본값 × 배수"로 보관**: `actual_success = base × 1.05`, 파괴는 비례 재분배한다. 넥슨이 공지하는 값이 기본값이므로 공지 대조가 쉽다.
3. **이벤트 = 확률/비용 변환기 체인**
   - `costMultiplier`, `destroyMultiplier(s≤21)`, `forceSuccess(s∈{5,10,15})`, `doubleStep(s≤10)`, `recoveryMesoMultiplier`를 조합 가능한 플래그로 둔다.
   - 샤타포스는 프리셋으로 둔다.
4. **할인 계산 함수 분리**
   - `(1 − (mvp+pc)) × eventMul`을 쓰고, MVP/PC방은 `s ≤ mvpMaxStar`(기본 16, 설정 가능)에만 적용한다.
   - 파방 추가분은 무할인이다.
5. **복구 정책은 사용자 선택 + 자동 최적화**: 기본(12성)과 확정(직전 성급) 중 하나를 성급별로 선택한다. 입력은 스페어 시세(노작값)다. MDP로 최적 정책을 제시한다.
6. **출력**: 기대 메소, 기대 파괴(=스페어 소모), 기대 시도 수, 분위수(P50/P90, 몬테카를로), "파괴 없이 도달할 확률"을 낸다.
7. **스탯 테이블**
   - 레벨 구간별(130/140/150/160/200/250) 누적 테이블로 저장한다.
   - 무기 15성 이하 공마는 기본공격력 기반으로 순차 계산한다.
   - **무기 고성급 등 빈 칸은 넥슨 Open API(장비 `starforce` 옵션 필드)에서 실측 수집**해 채운다. 01_nexon_open_api.md와 연계한다.
8. **레벨 L**: 착용 레벨 그대로 쓰는 것이 현행으로 보인다. 과거에는 10 단위 내림을 했다. 단위 테스트로 140제 12성 = 13,051,200을 고정한다.
9. **슈페리얼/놀장은 후순위**다. 별도 모듈로 두고, 하락과 찬스타임이 있는 체인을 쓴다(슈페리얼은 하락이 있어 순수 후진 계산 불가, 연립방정식 필요).
