# 07. 넥슨 Open API 키 정책 · 확장 시나리오 · 도전자 장비

> 조사일: 2026-10-15
> 표기: **[확인]** = 넥슨 공식 페이지 원문으로 확인 / **[커뮤니티]** = 커뮤니티·서드파티 사이트·나무위키 / **[미검증]** = 근거를 찾지 못했거나 추정
> 약관 원문은 `https://openapi.nexon.com/ko/support/terms/`에서 2026-10-15에 내려받아 인용했다(부칙: "본 약관은 2024년 9월 9일부터 적용됩니다.").

---

## 개요

- 넥슨 Open API 키는 **애플리케이션 단위**로 발급된다. 타입은 **개발 단계**(5건/초, 1,000건/일)와 **서비스 단계**(500건/초, 20,000,000건/일) 두 가지다. 허용량은 **애플리케이션별로 합산**된다. [확인]
- 서비스 단계 키는 **유효한 서비스 URL, 애플리케이션 설명, API 활용 목적**을 적으면 발급된다. 가이드에는 별도 심사나 운영 실적 요건이 적혀 있지 않다. [확인] (심사가 실제로 없는지는 [미검증])
- 약관 제5조①②는 **자기 키를 타인에게 제공·공개·공유하는 것**과 **타인의 키를 사용하는 것**을 금지한다. 단 "일부 API"는 키 소유자가 공개를 허용하면 예외다. [확인]
- 이 때문에 "사용자가 자기 키를 입력하는(BYOK)" 모델은 **회색지대**다. 큐브·스타포스 히스토리처럼 키 소유자 계정 기준으로 조회하는 API에서는 커뮤니티 사이트들이 실제로 이 방식을 쓰고 있다. [커뮤니티]
- **출처 표기**("Data based on NEXON Open API")는 의무다. MapleStory API 페이지에는 **"크롤링 데이터 30일 이내 갱신 의무"** 고지가 있다. [확인]
- 도전자의 장비는 하이퍼 버닝/챌린저스 시즌의 **"아이템 버닝" 기간제 지급 장비**다. 미션 달성에 따라 자동으로 성장하며, 직접 강화(스타포스 등)는 불가능하다. [확인]+[커뮤니티]

## A. 개인용을 넘어서는 확장: 키 타입과 한도

### A-1. 키 타입별 한도 [확인]

출처: https://openapi.nexon.com/ko/guide/prepare-in-advance/

| 애플리케이션 타입 | 초당 최대 허용량 | 1일 최대 허용량 | 등록 시 입력 항목 |
|---|---|---|---|
| 개발 단계 | 5건 / 초 | 1,000건 / 일 | 서비스명 |
| 서비스 단계 | 500건 / 초 | 20,000,000건 / 일 | 서비스명, 개발 환경, URL 정보, 소개, 대표 이미지 |

원문 인용:
- "향후 Open API를 호출할 때 http 헤더에 API Key를 포함해서 전송해야 하며, **API 허용량은 애플리케이션별로 합산됩니다.**"
- "API Key는 등록한 애플리케이션별 최대 2개 발급받을 수 있으며, 하나의 넥슨 ID에 동일 게임의 애플리케이션을 최대 3개까지 등록할 수 있습니다."
- "애플리케이션 개발이 종료되고, 서비스 단계로 변경될 경우 신규 발급을 통해 API Key를 새로 발급받아야 합니다."

정리하면 다음과 같다.
- 한도는 **애플리케이션 단위**로 적용된다. 한 앱의 키 2개는 같은 한도를 나눠 쓴다. [확인]
- 넥슨 ID 하나로 같은 게임의 앱을 최대 3개 등록할 수 있다. 앱 여러 개를 만들어 한도를 늘리는 것은 약관 제5조⑧(과부하·우회 접속 금지)과 ⑩에 비추어 권장하지 않는다. [미검증: 명시적 금지 조항은 없다]
- 한도를 넘기면 `429 / OPENAPI00007 (API 호출량 초과)`가 반환된다. [확인] https://openapi.nexon.com/ko/guide/request-api/

### A-2. 서비스 단계 신청 방법 [확인]

원문: "애플리케이션 신규 등록 시, 발급 희망 애플리케이션 타입을 서비스로 선택한 후, **유효한 서비스 URL과 애플리케이션 설명 및 API 활용 목적을 모두 기재하면 발급됩니다.** 서비스 URL이 아직 없을 수 있는 개발 단계에서는 개발 애플리케이션 타입을 사용한 후, 서비스 URL이 준비된 시점에 서비스 애플리케이션 타입으로 새로 등록하여 사용하는 것을 추천합니다."

- **서비스 URL 필요**: 예. "유효한" URL이어야 한다. [확인]
- **심사·기간**: 가이드에는 키 발급 심사나 대기 기간이 적혀 있지 않다. [미검증] 사이트 UI 문자열에서 확인된 "심사"는 **Apps 게시판 공개 노출** 심사뿐이다. 원문: "공개 설정 시 내부 정책에 따른 심사를 거친 뒤, Apps 게시판에 노출됩니다." [확인: openapi.nexon.com 페이지 내 i18n 문자열]
- **운영 중인 서비스 필요 여부**: 명시되어 있지 않다. 다만 "유효한 서비스 URL"을 요구하므로 최소한 접속 가능한 페이지는 있어야 할 것으로 보인다. [미검증]
- 커뮤니티 사례: Maple Support 가이드는 **사용자에게** "서비스 유형: 서비스", URL `https://maple.support`, 목적 "사용한 큐브 데이터 이력 확인을 위한 API KEY 발급"을 입력해 키를 발급받으라고 안내한다. 즉 일반 사용자도 서비스 단계 키를 바로 발급받을 수 있는 것으로 보인다. [커뮤니티] https://maple.support/apikey-guide

### A-3. 그 외 공식 채널: 프렌즈 프로그램 / NEXON Open ID [확인]

- Open API 사이트에는 "프렌즈 프로그램 신청"(https://openapi.nexon.com/ko/support/friends-registration/) 메뉴와 **NEXON Open ID**(OAuth2, `https://openid.nexon.com/oauth2/authorize`) 개발 가이드가 있다. [확인]
- "게임 데이터 활용 로그인"은 사용자가 넥슨 계정으로 로그인하고 동의하면 서비스가 그 사용자의 게임 데이터를 쓸 수 있게 하는 구조다. 원문: "게임 데이터 활용 로그인은 **지정된 프렌즈 제작자에게만 제공**되고 있습니다." 지정 서비스(2025-02-27 기준)는 **메이플지지, 메애기, 츄츄지지, 메이플 히스토리**다. [확인: openapi.nexon.com 페이지 내 문자열]
- Open ID 데이터 항목으로는 `maplestory.characterlist`, `maplestory.starforce`(/history/starforce), `maplestory.potential`, `maplestory.cube`, `maplestory.achievement`, `maplestory.scheduler`, `maplestory.soulpotential`이 있다. [확인]
- 테스트 사용자는 "제작자 본인을 제외하고 최대 5명까지 등록 가능"하다. [확인] 프렌즈 자격 취득 조건이나 심사 기준은 찾지 못했다. [미검증]

## B. "Bring Your Own Key" 허용 여부와 약관 조항

출처: https://openapi.nexon.com/ko/support/terms/ (2024-09-09 시행) [확인]

### B-1. 키 공유·양도 관련 원문

> **제5조 ①** 이용자는 자신이 발급 받은 API Key를 타인에게 제공, 공개하거나 공유할 수 없습니다. 단, 일부 API의 경우 API Key 소유자가 공개를 허용할 경우 API Key를 타인에게 제공할 수 있으며, 타인에게 제공 가능한 API Key는 Open API 공지사항 또는 내 애플리케이션 페이지를 통해 확인할 수 있습니다.

> **제5조 ②** 이용자는 자신이 발급 받은 API Key가 타인에 의하여 도용 당하지 않도록 관리하여야 하며, 타인이 발급받은 API Key를 이용해서는 안 됩니다. 단, 일부 API의 경우 API Key 소유자가 공개를 허용할 경우 API Key를 타인에게 제공할 수 있으며, (이하 동일)

> **제10조 (양도의 금지)** 이용자는 본 약관에 의해 체결된 계약상 권리 및 의무 등 일체의 계약상 지위를 회사의 동의 없이 제3자에게 양도할 수 없습니다.

해석은 다음과 같다. 이 부분은 법률 자문이 아닌 조사자 해석이다.
1. **"키 보유자 = 서비스 운영자"를 요구하는 명시 조항은 없다.** 다만 ①②에 따라 **운영자가 남의 키를 받아 운영자 서버에서 쓰는 것**은 원칙적으로 금지된다. 예외는 "일부 API"이고, 그 범위는 공지사항이나 내 애플리케이션 페이지에서 확인해야 한다. 공지 목록은 JS 렌더링이라 해당 공지를 직접 찾지는 못했다. [미검증]
2. 예외의 대상으로 가장 유력한 것은 **키 소유자 계정 기준으로 동작하는 API**다. `/maplestory/v1/ouid`, `/character/list`, `/history/starforce`, `/history/potential`, `/history/cube`, `/history/soul-potential` 등은 헤더의 키로 계정을 식별한다(스펙 YAML의 `/maplestory/v1/ouid`: "계정 식별자(ouid)를 조회합니다", 파라미터는 `x-nxopen-api-key`뿐). [확인: https://openapi.nexon.com/static/api/maplestory/17_ko_script20260918020020.yaml] 커뮤니티 BYOK 사이트들도 대부분 이 히스토리 API용이다. [커뮤니티]
3. **캐릭터 장비 조회처럼 키와 무관한 공개 데이터 API**를 위해 사용자 키를 운영자 서버로 받는 것은 ①의 "타인에게 제공"에 해당할 소지가 크다. [미검증: 넥슨 공식 해석은 찾지 못함]
4. 반대로 **키가 사용자 기기 밖으로 나가지 않는 로컬 프로그램**(데스크톱 앱이나 브라우저 로컬 저장소에서 사용자가 자기 키로 직접 호출)은 사용자 본인이 자기 키를 쓰는 것이다. 따라서 ①②의 "제공/타인 키 사용"에 해당하지 않는다고 볼 여지가 크다. [미검증] 이 경우 각 사용자가 약관상 "이용자"가 되고 각자의 앱 등록 정보를 갖는다.
5. 확실히 하려면 `help_openapi@nexon.co.kr`(약관 제6조⑤에 기재된 1:1 문의 주소)로 문의하는 것을 권장한다.

### B-2. 데이터 저장·캐싱

> **제5조 ⑤** 이용자는 회사의 사전 동의 없이 API 서비스의 결과 데이터(…)를 본 약관에서 허용한 범위를 넘어서서 무단으로 복제, 저장, 가공, 배포하거나 프로그램 등을 통해 API 서비스를 다시 제 3자에게 제공하는 행위는 할 수 없습니다.

> **제11조 ③** 이용계약이 해지되거나 API 서비스가 중단된 경우 이용자는 프로그램 등에서 API 사용을 즉시 중단하고 API 및 API 서비스를 이용한 결과 데이터 일체를 삭제하여야 합니다.

> **MapleStory API 페이지 고지**: "고지: API를 통해 데이터를 크롤링한 경우 **30일 이내에 크롤링한 데이터를 갱신해야 할 의무**가 있습니다." [확인] https://openapi.nexon.com/ko/game/maplestory/

- 약관 본문에는 구체적인 캐시 TTL 조항이 없다. 게임 페이지 고지상 **저장 데이터는 30일 이내 갱신**해야 한다. [확인] "30일 후 삭제" 규정은 찾지 못했다. [미검증]
- "프로그램 등을 통해 API 서비스를 다시 제3자에게 제공"하는 것은 금지다. 즉 **우리 서버를 프록시/재판매 API로 여는 것은 불가**하다. [확인]

### B-3. 출처 표기

> **제6조 ④** 이용자는 프로그램 등 및 API 서비스를 이용한 결과 데이터에 회사가 별도로 정하는 방법에 따라 "NEXON Open API"를 이용한 것임을 명시해야 하며, 회사의 브랜드를 모방, 도용하여서는 안 됩니다.

> **가이드(API 사용하기)**: "제작 시 데이터를 NEXON Open API에서 제공 받았음을 애플리케이션 내에 명시해주셔야 합니다. … 서비스 및 애플리케이션에 **'Data based on NEXON Open API'**라는 문구를 명시해주시길 바랍니다." [확인] https://openapi.nexon.com/ko/guide/request-api/

### B-4. 상업적 이용

> **제5조 ③** 이용자는 프로그램 등을 제공하면서 그 사용자들로부터 API 서비스 이용에 대한 대가 및 프로그램 등의 이용에 대한 대가(금전, 정보 제공 등 일체의 유·무형의 대가)를 제공 받을 시 홈페이지 내 안내된 내용에 따라야 하며, 게임 IP 사용 가이드 등 회사가 정한 정책 및 관련 법령을 위반하여서는 안됩니다.

> **제6조 ⑥** 이용자는 API 서비스를 이용하면서 얻은 일체의 데이터 및 저작물 등을 회사의 승낙 없이 영리 목적으로 이용하거나 회사가 허락한 경우 및 그 범위를 초과하여 제3자에게 이용하도록 할 수 없습니다.

- 유료화나 광고 수익은 **회사 승낙 또는 홈페이지 안내 범위 내**에서만 가능하다.
- **(2026-10-15 추가 확인) 무료 서비스 + 광고:**
  - 약관 원문은 "얻은 데이터를 회사 승낙 없이 영리 목적으로 이용"하는 것을 금지한다. 광고만 따로 허용하거나 예외로 둔다는 문구는 찾지 못했다. [확인]

## C. API 키 발급 절차 (단계별)

출처: https://openapi.nexon.com/ko/guide/prepare-in-advance/ , https://openapi.nexon.com/ko/guide/request-api/ [확인]

1. **넥슨 ID 로그인**: https://openapi.nexon.com 우측 상단 '로그인'. 넥슨 ID가 없으면 회원가입한다. 원문: "NEXON Open API를 활용하려면 NEXON 계정으로 로그인해야 합니다."
2. **내 애플리케이션 > 애플리케이션 등록** 클릭
3. **게임 선택**: 메이플스토리
4. **애플리케이션 타입 선택**: 개인용이면 '개발 단계'(서비스명만 입력). 공개 서비스면 '서비스 단계'(서비스명, 개발 환경, URL, 소개, 대표 이미지).
5. **이용약관 동의 후 등록**: "애플리케이션 등록이 정상적으로 완료되면 API Key가 자동으로 발급됩니다."
6. **키 확인**: 내 애플리케이션 > 애플리케이션 목록 > 상세 페이지. 유출되면 같은 곳에서 추가 키를 발급받아 교체한다.

- **본인인증 / 넥슨 ID 종류**: 가이드에는 "넥슨 ID로 로그인"만 있고 별도 본인인증 요구는 없다. [미검증] 넥슨 통합 회원 약관상의 요건(미성년자 등)은 확인하지 않았다.
- **활성화 대기 시간**: "자동 발급"이라고만 되어 있고 대기 시간 언급은 없다. [확인/미검증] 체감상 즉시 사용 가능하다는 커뮤니티 안내가 많으나 근거 원문은 확보하지 못했다.
- **웹에서 테스트**: 게임 > 메이플스토리 > API 선택 > *Try it out* > 파라미터 입력 > *Execute*. 원문: "테스트 기능은 넥슨 ID로 로그인하고, 테스트를 희망하는 API의 API Key를 발급 받은 상태에서만 사용할 수 있습니다." [확인]

### curl 테스트 예시

헤더 이름 `x-nxopen-api-key`와 베이스 URL `https://open.api.nexon.com`은 [확인]이다. 아래 명령 자체는 그 정보를 조합한 예시다.

```bash
export NXOPEN_KEY="발급받은_API_KEY"

# 1) 캐릭터 이름 → ocid (한글은 URL 인코딩 필요)
curl -s -G "https://open.api.nexon.com/maplestory/v1/id" \
  --data-urlencode "character_name=캐릭터명" \
  -H "x-nxopen-api-key: $NXOPEN_KEY"
# → {"ocid":"..."}

# 2) 장착 장비 조회
curl -s "https://open.api.nexon.com/maplestory/v1/character/item-equipment?ocid=<OCID>" \
  -H "x-nxopen-api-key: $NXOPEN_KEY"

# 3) (키 소유자 본인 계정) 스타포스 강화 기록
curl -s "https://open.api.nexon.com/maplestory/v1/history/starforce?count=10&date=2026-10-14" \
  -H "x-nxopen-api-key: $NXOPEN_KEY"
```

API 스펙상 참고사항 [확인] (https://openapi.nexon.com/static/api/maplestory/14_ko_script20260917040003.yaml , 17_ko_script20260918020020.yaml):
- "메이플스토리 게임 데이터는 평균 15분 후 확인 가능합니다."
- "전일 데이터는 다음날 오전 2시부터 확인할 수 있습니다."
- "게임 콘텐츠 변경으로 ocid가 변경될 수 있습니다." 따라서 ocid를 영구 캐시하지 말아야 한다.
- 스타포스 강화 결과는 "2023년 12월 27일 데이터부터 조회 가능하며, 최대 2년동안의 데이터만 제공", 큐브 결과는 "최근 2년 데이터만 조회 가능"하다.

## 우리 프로그램에 대한 결론 / 권장안

### 시나리오 1: 개인용 (본인 1명)
- **개발 단계 키로 충분하다**(1,000건/일, 5건/초). 캐릭터 1명의 장비, 스탯 등 10~20개 엔드포인트를 하루 수십 회 갱신해도 여유가 있다.
- 키는 `.env` 또는 OS 키체인에 보관하고 git에 커밋하지 않는다. 앱 하단에 "Data based on NEXON Open API"를 표기한다.
- 응답을 로컬 캐시하되 **30일 이내 갱신**하고, ocid는 주기적으로 재조회한다.

### 시나리오 2: 지인 몇 명 (2~10명)
- **권장안 A (가장 안전)**: **각자 자기 키를 발급받아 각자 로컬에서 실행**한다. 키를 자기 기기에만 저장하고 넥슨에 직접 호출한다. 키가 운영자에게 전달되지 않으므로 제5조①②와의 충돌 소지가 가장 적다. [해석/미검증]
  - 앱에 "키 발급 가이드"(C절)와 키 입력 화면을 제공한다. 키는 로컬 암호화 저장소에만 두고 서버나 로그로 전송하지 않는다.
- **피해야 할 것**: 내 키 하나를 지인들에게 나눠주는 것(제5조① 위반 소지 높음). 내 서버가 지인들의 키를 받아 대신 호출하는 것(①② 위반 소지).
- 개발 단계 키 1개로 내 서버가 지인 몇 명의 **공개 캐릭터 데이터**를 조회해 보여주는 것은 "프로그램 등"을 제공하는 형태다. 약관상 막혀 있지는 않으나 1,000건/일 한도가 빠듯할 수 있다.

### 시나리오 3: 공개 서비스
- **운영자 명의의 서비스 단계 키**(500건/초, 2천만 건/일)를 쓴다. 공개 도메인 URL, 설명, 활용 목적을 갖춰 신규 등록한다. 개발 키에서 전환되지 않으므로 새로 발급받아야 한다.
- 캐릭터 장비처럼 **키와 무관한 공개 데이터는 운영자 키로 서버에서 호출하고 캐싱**한다(30일 이내 갱신). 사용자 키를 받을 필요가 없다.
- 사용자 **본인 계정 데이터**(큐브·스타포스 기록, 캐릭터 목록)가 필요하면 우선순위는 다음과 같다.
  ① **프렌즈 프로그램 + NEXON Open ID(넥슨 로그인)** 정식 경로
  ② 그 전까지는 클라이언트 측에서만 사용자 키를 쓰는 BYOK. 서버 미전송, 미저장을 명시한다.
  서버에서 사용자 키를 받아 저장하는 방식은 비권장이다.
- 필수 사항: "Data based on NEXON Open API" 표기, 넥슨 브랜드 모방 금지, 우리 API를 3자에게 재제공하지 않기, 과도한 주기 폴링 금지, 유료화나 광고 전 넥슨 정책 확인.
- 출시 전 `help_openapi@nexon.co.kr`에 BYOK 허용 범위와 수익화 가능 여부를 서면으로 문의하는 것을 권장한다.

8. "30일 이내 갱신" 고지가 캐시 전반에 적용되는지, 크롤링에만 해당하는지 범위가 모호함. 보수적으로 전부 적용을 권장. [미검증]

  - 응답 헤더: `access-control-allow-origin: <요청 origin>`, `access-control-allow-headers: x-nxopen-api-key`
  - → **브라우저 JS에서 키 헤더를 붙여 직접 호출할 수 있다** [확인: 직접 테스트].
- 따라서 "사용자 키를 브라우저 세션에만 보관하고 우리 서버를 거치지 않는" 구조를 기술적으로 구현할 수 있다.
  - 이 경우 키가 운영 서버로 전달되지 않는다.
  - 다만 약관상 허용 여부는 여전히 넥슨 확인이 필요하다.
