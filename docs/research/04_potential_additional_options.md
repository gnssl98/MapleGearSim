## 2. 잠재능력 상세

### 2.1 등급과 줄 구성
- 등급은 레어, 에픽, 유니크, 레전드리 4단계다. 등급이 오를 때는 한 번에 한 단계만 오른다.
- 옵션은 3줄이다. 각인의 인장이 삭제된 2025-10 이후로는 별도 아이템 없이 3줄이 된다고 한다[커뮤니티].
- **줄별 옵션 등급 설정 확률** [공식, 블랙 큐브·잠재능력 재설정·프라임 큐브 공통]:

| 줄 | 아이템 등급과 같은 등급(이탈) | 한 단계 낮은 등급 |
|---|---|---|
| 1번째 | 100% | 0% |
| 2번째 | 20% | 80% |
| 3번째 | 5% | 95% |

- 레드 큐브는 2번째 줄 10%, 3번째 줄 1%다(단종).
- 에디셔널 재설정, 에디셔널 큐브, 화이트 에디셔널은 1번째 줄 100%다. 2·3번째 줄은 아이템 등급에 따라 다음과 같다. 레전드리는 2·3번째 줄 모두 **레전드리 0.4975%** / 유니크 99.5025%다. 유니크는 1.9608% / 98.03922%, 에픽은 4.7619% / 95.2381%다. [공식]

### 2.2 재설정 수단과 등급 상승 확률·천장 [공식]

- 천장 카운트는 수단별·등급별로 저장되고 **같은 월드의 캐릭터끼리 공유**된다. 보장되지 않은 등급 상승이 일어나면 초기화된다. [공식]
- 보장 횟수는 "N회째 재설정에서 보장"으로 해석한다. 나무위키의 메소 천장 비용(유→레 107회 × 4,250만 = 45.48억)과도 맞는다.

### 2.4 미라클 타임
- 과거(2024-05-05) 공식 결과를 보면 **등급 상승 확률만 2배**였다. 블랙은 30% / 7% / 2.8%, 레드는 12% / 3.6% / 0.6%, 에디셔널은 9.524% / 3.922% / 1.4%, 명장은 15.999% / 3.392% / 0.399%였다. 옵션 확률은 변하지 않는다. [공식 아카이브]
- 현재는 썬데이 메이플이나 '장비별 미라클 타임'(특정 부위 한정) 형태로 가끔 열린다. 2026-09-17 공지에 따르면 펄스 인핸서 강화에는 미라클 타임이 적용되지 않고, 소울 잠재능력에는 적용된다. [공식]
- 미라클 타임 동안 메소 재설정 비용이나 천장 카운트가 어떻게 처리되는지(비용 할인 여부, 천장 2배 적용 여부)를 다룬 공지는 찾지 못했다. [확인 필요]
- 시뮬레이터에서는 `p_upgrade × 2`를 옵션으로 제공하는 정도로 충분하다.

### 2.5 옵션 확률표 (공식, 2026-10-15 조회)
공식 페이지 `maplestory.nexon.com/Guide/OtherProbability/cube/{red|black|addi|master|artisan|strange|strangeAddi}` 안의 확률 검색은 아래 POST 엔드포인트를 호출한다. 이 엔드포인트로 **등급 × 부위(20종) × 레벨(0~250)별 전체 옵션 확률표**를 HTML로 받을 수 있다.

```
POST https://maplestory.nexon.com/Guide/OtherProbability/cube/GetSearchProbList
form: nCubeItemID=<5062010 블랙|5062009 레드|5062500 에디셔널|2711003 명장|2711004 장인|2711000 수상한|2730002 수상한 에디>
      nGrade=<1 레어|2 에픽|3 유니크|4 레전드리>
      nPartsType=<1 무기|2 엠블렘|3 보조(포실·소울링 제외)|4 포스실드·소울링|5 방패|6 모자|7 상의|8 한벌옷|9 하의|10 신발|11 장갑|12 망토|13 벨트|14 어깨|15 얼굴|16 눈|17 귀고리|18 반지|19 펜던트|20 기계심장>
      nReqLev=<0~250>
```
- 응답 표의 확률은 각 줄의 **절대 확률**이다. 2·3번째 줄 표에는 하위 등급 옵션과 동일 등급 옵션이 모두 들어 있다(이탈 확률이 이미 곱해져 있다).
- **옵션 제한 규칙** [공식]:
  - 다음 옵션은 세 줄 중 최대 1개만 붙는다: 쓸만한 스킬 계열, 피격 후 무적시간 증가.
  - 다음 옵션은 세 줄 중 최대 2개까지 붙는다: 피격 시 일정 확률로 데미지 % 무시, 피격 시 일정 확률로 일정 시간 무적.
  - 앞 줄에서 제외된 옵션이 있으면 남은 옵션의 확률은 `표기확률 / (100% − 제외된 옵션 표기확률 합)`으로 다시 계산한다.
  - 방무·보공·드롭률의 2줄 제한은 2024-01에 해제됐다.
- 레벨 구간: 수치는 대체로 **120~249**(예: 레전 주스탯 12%)와 **250 이상**(13%)으로 나뉜다. 그보다 낮은 구간은 나무위키 "잠재능력/옵션 목록"에 0~30 / 31~70 / 71~200(200까지 9%/12%)으로 정리돼 있다.

#### (1) 레전드리 무기, 레벨 200 (블랙 큐브·메소 재설정)
1번째 줄(레전드리 옵션):

| 옵션 | 확률 |
|---|---|
| STR/DEX/INT/LUK +12% | 각 9.7561% |
| 공격력/마력 +12% | 각 4.8780% |
| 크리티컬 확률 +12% / 데미지 +12% | 각 4.8780% |
| 올스탯 +9% | 7.3171% |
| 공격력/마력 +32 | 각 4.8780% |
| 몬스터 방어율 무시 +35% / +40% | 각 4.8780% |
| 보스 몬스터 데미지 +35% | 9.7561% |

## 6. 기댓값 계산 방법

### 6.1 등급 상승(천장 포함)
등급 상승 확률이 p이고 N회째에 보장(천장 N)되면, 성공까지 시도 횟수 T의 분포는 다음과 같다.
- P(T = k) = (1−p)^(k−1) · p (k < N)
- P(T = N) = (1−p)^(N−1)

기댓값은 E[T] = Σ_{k=0}^{N−1} (1−p)^k = **(1 − (1−p)^N) / p** 이다(devcomma가 쓰는 식과 같다).

[계산] 메소 재설정 기준:

| 구간 | p | N | E[T] |
|---|---|---|---|
| 잠재 레→에 | 15% | 10 | ≈ 5.35회 |
| 잠재 에→유 | 3.5% | 42 | ≈ 22.2회 |
| 잠재 유→레 | 1.4% | 107 | ≈ 55.6회 |

비용은 Σ E[T] × (해당 등급의 1회 비용)이다. 예를 들어 200제 유→레는 약 55.6 × 3,825만 ≈ **21.3억 메소**이고, 천장 최대치는 107 × 3,825만 = 40.9억이다.

- 에디 메소 재설정도 같은 식을 쓴다. 레→에 (p = 2.381%, N = 62)는 ≈ 32.6회, 에→유 (0.9804%, 152)는 ≈ 79.2회, 유→레 (0.7%, 214)는 ≈ 111.1회다. 200제 에디 유→레는 111.1 × 7,480만 ≈ 83.1억 메소다.
- 천장 카운트가 **월드 공유이고 남은 횟수를 이어받는다**는 점을 반영하려면, 사용자가 현재 카운트 n0를 입력하게 하고 N 대신 N − n0를 넣는다.

### 6.2 옵션 목표 달성 확률
1. 공식 확률표에서 줄 i의 옵션 분포 L_i를 만든다(동일 등급 옵션과 하위 등급 옵션의 절대 확률).
2. (L1 × L2 × L3)를 열거한다. 각 표가 30~60개라 많아야 수만 가지 조합이다. 이때 제한 규칙(최대 1개, 최대 2개 그룹)에 따라 확률을 다시 정규화한다.
3. 목표 술어(예: 주스탯 합 ≥ 33, 올스탯 포함)를 만족하는 확률 q를 더한다.
4. 레전드리를 유지한 채 재설정하면 매회 독립이므로 기대 횟수는 1/q이고 기대 비용은 cost_legend / q다. 선택형이라 기존 옵션을 지킬 수 있으므로 "목표 이상이면 멈춤" 정책이면 기하분포가 그대로 맞는다.
5. 프라임 큐브는 1번째 줄을 고정하고 L2 × L3만 열거한다.
6. 등급 상승과 옵션 목표를 함께 다루려면 등급을 상태로 하는 마르코프 체인으로 본다. 상위 등급에 도달한 직후의 옵션도 목표를 만족할 수 있는데, 대부분의 계산기는 이 부분을 무시한다.

## 7. 프로그램 설계 시 시사점
1. **데이터 소스**: 옵션 확률은 공식 POST 엔드포인트(`GetSearchProbList`)를 크롤링해 버전별 JSON으로 저장한다. 크롤링 날짜와 패치 버전을 메타데이터로 남긴다. 등급 상승 확률과 천장, 비용은 설정 파일로 둔다(패치 때 수동 갱신).
2. **수단 모델**: `ResetMethod { id, grade_up_p[3], pity[3] | null, cost_by_level_grade | null, currency(meso/credit/coin/item), selectable(bool), fixed_first_line(bool), allowed_grades, line_grade_p[2] }`
   - 메소 재설정, 프라임, 골드/실버, 카르마 블랙 등을 같은 인터페이스로 다룬다.
3. **옵션 매칭**: 옵션 문자열을 `{stat, value, unit}`으로 파싱한다. 올스탯%는 주스탯%에 합산한다(공식 자동 재설정도 이렇게 계산한다). 쿨감은 초 단위로, 크뎀과 드메는 별도 키로 둔다.
4. **계산 방식**: 단일 아이템은 정확 열거로 계산한다(빠르고 정확하다). 다중 아이템이나 정책 비교(예: "33 미만이면 계속" 대 "30이면 멈춤")는 몬테카를로로 보완한다.
5. **천장 상태**: 월드 공유 카운트를 사용자가 입력할 수 있게 한다. 메소 재설정과 큐브(카르마 블랙)는 카운트를 따로 센다는 점을 반영한다.
6. **미라클 타임 토글**: 등급 상승 확률 × 2. 천장 처리는 미확인이므로 옵션으로 둔다.
7. **추옵**: 4.1의 단계 확률, 옵션 개수, 19종 균등 풀, 레벨 공식으로 정확 열거한다(약 3,876조합 × 단계^4). 급수 계수는 사용자가 설정한다. 무기 공 추옵은 무기별 기본 공격력 표가 필요하다(별도 데이터).
8. **비용 환산**: 크레딧, 캐시, 코인 아이템(프라임, 카르마 큐브)은 메소로 바로 바꿀 수 없다. 사용자가 "메소 환산 단가"를 입력하게 하거나 별도 통화로 집계한다.
9. **자동 재설정 정책**: 공식 자동 재설정은 "목표 수치 합보다 높으면" 멈추고, 추옵은 "모든 목표를 만족하면" 멈춘다. 시뮬레이터도 같은 정책을 제공하면 인게임 경험과 맞출 수 있다.
10. **Open API 활용**: 넥슨 Open API의 강화 이력 엔드포인트로 사용자 실측 이력을 가져와 경험적 확률이나 지출을 검증하는 기능을 고려할 수 있다. 확률표 자체를 주는 엔드포인트는 확인하지 못했다(아래 8번 참고).

## 8. 불확실 / 추가 확인 필요 항목
- **Nexon Open API**: 서드파티 래퍼에는 `/maplestory/v1/history/cube`, `/history/potential`, `/history/starforce`(커서 페이지네이션, `date_kst`, `count`)와 구 `cube-use-results`가 알려져 있다. 그런데 키 없이 요청하면 존재하지 않는 경로도 똑같이 `OPENAPI00004`를 반환해서 존재 여부를 확인하지 못했다. 문서 사이트(openapi.nexon.com)의 "확률 정보 조회"(id=17)는 JS로 렌더링돼 내용을 확인하지 못했다. 이 엔드포인트들은 **사용 이력**(재설정 전후 옵션, 미라클 여부 등)을 주는 것이고 **확률표를 주는 것은 아닌 것으로 보인다**. API 키로 직접 검증해야 한다(문서 01 참고).
- 2026-10 기준 메소 재설정 **비용 표가 2024년 이후 바뀌었는지** 확인해야 한다(인게임 확인 필요).
- 미라클 타임 동안 메소 재설정의 등급 상승 2배가 적용되는지, 천장 카운트를 어떻게 다루는지 확인해야 한다. 2025-09 UI 개편 이후 오류 사례도 있었다.
- 장인의 큐브와 실버 큐브의 유→레 가능 여부와 확률을 확인해야 한다.
- 에디셔널 250제 수치(주스탯%, 공 고정치)와 레벨 구간(160~199와 200~249의 차이)을 공식 POST로 레벨을 바꿔 다시 수집해야 한다.
- 무기 공/마 추옵 단계별 % 공식(나무위키 식은 모호함), 방어구 공/마 추옵 = 단계인지, 추옵의 단계별 독립 여부, 4개 옵션의 비복원 추출 가정을 확인해야 한다.
- 추가옵션 재설정 3,000,000 메소가 정말 레벨과 무관한지(공지에는 단일 금액만 있음)와 대상 아이템 범위를 확인해야 한다.
- 심연의 환불이 선택형인지 확인해야 한다.
- 놀장, 익셉셔널, 소울 잠재능력, 황금망치의 현재 현황과 확률은 이번 조사에서 충분히 확인하지 못했다.
- 귀속의 표식은 테스트월드 공지만 확인했다. 본서버에 적용됐는지 확인이 필요하다.
